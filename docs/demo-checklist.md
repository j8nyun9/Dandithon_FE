# 제출 전 시연 점검표

로컬 검사 통과와 배포 환경 동작 확인을 구분합니다. 아래 항목은 실제로 확인한 후 체크합니다.

- [ ] 새 브라우저에서 배포 홈이 열리고 로그인 없이 대학 순위를 확인한다.
- [ ] 비로그인 의연록에 로그인 안내가 표시된다.
- [ ] 학생 계정으로 로그인하고 마이페이지 이름·학교가 해당 계정과 일치한다.
- [ ] 관심 분야를 선택해 추천받고 카드에 추천 이유가 표시된다.
- [ ] 개발자 도구 Network의 `/api/ai/recommend` 응답에서 `data.mode`가 `live`임을 확인한다. 토큰·키가 포함된 화면은 발표 자료에 노출하지 않는다.
- [ ] 서로 다른 참여 이력의 학생 두 명으로 추천을 비교한다. 적합한 이유인지 확인하며, 반드시 서로 다른 추천이 나온다고 가정하지 않는다.
- [ ] 로컬 별도 환경에서 AI 미설정 시 기본 추천 안내가 표시되는지 확인한다.
- [ ] 학생이 공식 신청 완료 표시 후 참여 인증을 요청한다. 실제 외부 신청은 원 사이트에서 별도로 진행한다.
- [ ] 관리자로 로그인해 해당 요청을 확인하고 승인한다. 실제 봉사 없이 시연할 때는 시연 활동만 사용한다.
- [ ] 학생으로 돌아와 마이페이지의 승인 상태와 리그·의연록 반영을 확인한다. 헌혈 제외 등 산정 규칙을 고려한다.
- [ ] 모바일에서 메뉴·카드·의연록 필터가 화면 밖으로 넘치지 않는다.
- [ ] 서버 중단·지연 시 오류 안내가 표시되고 복구 후 다시 조회할 수 있다.
- [ ] Render 최신 배포 커밋, `/api/health`, 학생 로그인, 추천을 발표 직전에 확인한다.

## 발표 설명

AI는 선택한 관심 분야와 승인된 분야별 참여 이력을 참고해 등록된 봉사활동을 추천하고 이유를 설명합니다. 실제 모델 응답과 기본 추천은 구분하여 표시합니다. 활동 완료 승인과 대학 리그 집계는 담당자 확인과 정해진 산정 규칙에 따릅니다.

## 배포 설정 확인

백엔드에 `NODE_ENV=production`, `HOST=0.0.0.0`, 영구 `DATABASE_URL`, 충분한 길이의 `DANDI_SECRET`을 설정합니다. 실제 AI 사용에는 `AI_MODE=live`, `OPENAI_API_KEY`, 지원되는 `OPENAI_MODEL`이 필요합니다. 키는 저장소·스크린샷에 넣지 않습니다.
프론트엔드의 `/api/*` 전달 규칙과 SPA 경로 재연결을 확인합니다. 무료 인스턴스의 대기 시간은 UI 수정만으로 제거되지 않습니다.
